# 0. 이번 주 수업에서 무엇을 하는가?

6주차에는 **챗봇을 만들지 않습니다.**

이번 시간의 목표는 다음과 같습니다.

```text
질문 1개
   ↓
관련 문서 검색
   ↓
검색된 문서
   ↓
LLM
   ↓

```

즉, **RAG의 핵심 구조를 이해하고 실제로 한 번 완성해 보는 것**이 목표입니다.

7주차에는 이 구조를 그대로 확장합니다.

```text
6주차
질문 1개 → RAG → 답변 1개

7주차
질문 1 → 답변 1
        ↓
질문 2 → 답변 2
        ↓
질문 3 → 답변 3
```

# 2. LLM만 사용하면 왜 부족한가?

대형 언어 모델은 매우 많은 데이터를 학습합니다.

하지만 모델이 모든 정보를 데이터베이스처럼 정확히 기억하는 것은 아닙니다.

다음과 같은 한계가 있습니다.

- 학습 이후의 최신 정보를 알지 못할 수 있음
- 회사 내부 문서, 학교 내부 자료 등 비공개 데이터를 알지 못함
- 답변의 출처를 확인하기 어려움
- 잘못된 내용을 사실처럼 생성할 수 있음
- 새로운 정보를 반영하려면 재학습이 필요할 수 있음

예를 들어 다음 질문을 생각해 봅시다.

```text
2026학년도 2학기 성적우수장학금 신청 기간은 언제인가요?
```

일반 LLM은 이 정보를 정확히 알지 못할 수 있습니다.

하지만 학교의 실제 공지문을 제공하면 어떨까요?

```text
질문
 +
학교 공지
 ↓
LLM
 ↓
공지 내용을 바탕으로 답변
```

이 아이디어가 RAG의 출발점입니다.

# 3. 외부 지식과 Retrieval

LLM이 모르는 정보를 외부 문서에서 찾아오는 과정을 **Retrieval**이라고 합니다.

```text
사용자 질문
    ↓
관련 문서 검색
    ↓
검색 결과 반환
```

RAG에서 중요한 점은 먼저 **정답을 생성하는 것이 아니라 관련 문서를 잘 찾는 것**입니다.

검색된 문서가 잘못되면 이후 답변도 잘못될 가능성이 높습니다.

---

# 4. RAG란 무엇인가?

RAG는 **Retrieval-Augmented Generation**의 약자입니다.

우리말로는 **검색 증강 생성**이라고 합니다.

이번 수업에서는 가장 단순한 형태인 **Basic RAG**만 다룹니다.

## 4.1 Retrieval

질문과 관련된 문서를 찾습니다.

```text
질문
 ↓
관련 문서 검색
```

## 4.2 Augmented

검색한 문서를 질문과 함께 LLM에 넣습니다.

```text
질문 + 검색된 문서
 ↓
LLM에 전달
```

## 4.3 Generation

LLM이 질문과 검색 문서를 바탕으로 답변합니다.

```text
질문 + 검색된 문서
 ↓
LLM
 ↓
답변
```

전체 흐름:

```text
Retrieval
   ↓
Augmented
   ↓
Generation
```

# 5. 이번 시간에 구현할 RAG 전체 구조

```text
[문서 준비]
     ↓
[Chunking]
     ↓
[Embedding]
     ↓
[Chroma Vector Store]
     ↓
-----------------------------
     ↓
[사용자 질문]
     ↓
[질문 Embedding]
     ↓
[관련 문서 검색]
     ↓
[질문 + 검색된 문서]
     ↓
[LLM]
     ↓
[답변]
```

이번 시간에 기억해야 할 핵심 용어는 6개입니다.

| 용어 | 의미 |
|---|---|
| Chunk | 긴 문서를 나눈 작은 문서 단위 |
| Embedding | 문장의 의미를 숫자 벡터로 변환 |
| Vector Store | 벡터를 저장하고 유사 문서를 검색 |
| Retrieval | 질문과 관련된 문서를 찾는 과정 |
| LLM | 검색된 문서를 바탕으로 답변 생성 |
| LangChain | 위 과정을 연결하기 쉽게 도와주는 프레임워크 |

# 6. Chunking

긴 문서를 한 번에 사용하면 다음과 같은 문제가 생길 수 있습니다.

- 검색 범위가 너무 넓어짐
- 불필요한 내용까지 함께 전달됨
- LLM 입력 길이가 길어짐
- 필요한 문장을 정확하게 찾기 어려움

따라서 문서를 작은 단위로 나눕니다.

```text
긴 문서
 ↓
Chunk 1
Chunk 2
Chunk 3
Chunk 4
```

예:

```text
[원본 문서]

2026학년도 2학기 성적우수장학금 신청 기간은
10월 5일부터 10월 12일까지입니다.

신청은 학생포털 장학 메뉴에서 진행합니다.

직전 학기 평점 3.5 이상인 재학생이 신청할 수 있습니다.
```

이 문서를 여러 Chunk로 나누어 검색에 활용할 수 있습니다.

> 이번 실습에서는 Chunk 크기를 세밀하게 조정하지 않습니다.  
> 먼저 **문서를 나누는 이유와 전체 흐름**을 이해하는 데 집중합니다.

---

# 7. Embedding

컴퓨터는 문장의 의미를 사람처럼 바로 이해하지 못합니다.

따라서 문장을 숫자 벡터로 변환합니다.

이를 **Embedding**이라고 합니다.

```text
"장학금 신청 기간"
        ↓
[0.12, -0.34, 0.56, ...]
```

Embedding의 목적은 의미가 비슷한 문장을 가까운 위치에 표현하는 것입니다.

예:

```text
장학금 신청 기간은 언제인가요?
성적우수장학금은 언제 신청하나요?
```

두 문장은 표현은 다르지만 의미는 비슷합니다.

Embedding을 사용하면 이런 의미적 유사성을 비교할 수 있습니다.

---

# 8. Vector Store

Embedding한 벡터를 저장하고 검색하는 곳이 **Vector Store**입니다.

Vector Store는 단순 저장만 하는 것이 아니라 다음 기능을 제공합니다.

- 벡터 저장
- 유사도 검색
- Metadata 저장
- 조건에 따른 필터링

이번 실습에서는 **Chroma**를 사용합니다.

## Chroma를 사용하는 이유

- 오픈소스
- Python에서 쉽게 사용 가능
- Colab에서 실습하기 쉬움
- LangChain과 연동이 쉬움
- RAG 실습에 적합

---

# 9. Retrieval은 어떻게 이루어지는가?

```text
1. 문서를 Chunk로 나눔
2. 각 Chunk를 Embedding
3. Chroma에 저장
4. 사용자 질문도 Embedding
5. 질문과 비슷한 Chunk 검색
6. 관련 문서 반환
```

예:

```text
질문:
장학금 신청 기간은 언제인가요?

        ↓

검색 결과:
2026학년도 2학기 성적우수장학금 신청 기간은
10월 5일부터 10월 12일까지입니다.
```

이제 검색된 문서를 LLM에 전달하면 됩니다.

# 10. LangChain은 무엇인가?

RAG를 직접 구현하려면 여러 단계를 연결해야 합니다.

```text
문서 로딩
 ↓
문서 분할
 ↓
Embedding
 ↓
Vector Store
 ↓
검색
 ↓
Prompt
 ↓
LLM
 ↓
답변
```

LangChain은 이 과정을 쉽게 연결할 수 있도록 여러 구성요소를 제공하는 프레임워크입니다.

이번 시간에는 다음 구조로 사용합니다.

```text
Document
 ↓
Text Splitter
 ↓
Embedding
 ↓
Chroma
 ↓
Retriever
 ↓
LLM
 ↓
Answer
```

7주차:

```text
사용자 질문
 ↓
Streamlit
 ↓
LangChain
 ↓
Chroma
 ↓
Ollama
 ↓
오픈소스 LLM
 ↓
답변
 ↓

 ↓
대화 계속
```

7주차에는 다음 도구를 사용합니다.

- Ollama
- LangChain
- Chroma
- Streamlit

| 구분 | 6주차 | 7주차 |
|---|---|---|
| 주제 | RAG 질의응답 | RAG 챗봇 |
| 환경 | Colab 중심 | 로컬 Ollama |
| 핵심 도구 | LangChain + Chroma | LangChain + Chroma + Ollama + Streamlit |
| 입력 | 질문 1개 | 연속 질문 |
| 출력 | 답변 1개 | 대화형 답변 |
| UI | 없음 | 있음 |
| 목표 | RAG 구조 이해 | RAG 서비스 형태 체험 |
| 팀활동 | 팀 문서로 RAG 테스트 | 팀 프로젝트 챗봇으로 확장 |
